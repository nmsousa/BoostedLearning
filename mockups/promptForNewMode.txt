# Kiro Implementation Prompt — Radial Vocabulary Learning Map

## Project Overview

I want to implement a new, fully interactive learning section in our existing language-learning application.

Our application is built using **Angular + Ionic for Android**, and this feature must integrate into the existing application without disrupting any of its current functionality.

The feature is inspired by a radial learning map concept: instead of following a traditional, long, linear learning journey, users explore a central vocabulary hub connected to multiple thematic learning units arranged in a circular layout.

The feature should feel like a polished, modern, gamified language-learning experience similar in quality to Duolingo, but with its own distinctive visual identity.

**Your task is to inspect the existing project, understand its architecture, and implement this feature directly into the current codebase.**

Do not create a separate application, replace existing navigation, or introduce unnecessary dependencies.

---

   - Angular version.

   - Existing home screen and navigation tabs.

3. Identify how existing learning sections are accessed.

Do not introduce a new backend or database solely for this feature.

If the current application has no suitable progress persistence mechanism, implement a lightweight solution consistent with the existing architecture, preferably using an existing storage service.

Do not overwrite or reset existing user progress.

# 2. Feature Concept

Create a new learning section called:

**Explore — Vocabulary Network**

The main screen should display a radial learning map.

At the center is a large circular node representing:

**Core Vocabulary**

Around it, arrange thematic learning units in a circular pattern, connected to the center by visible lines.

The overall layout should resemble a colorful, modern, game-inspired learning map.

The central node represents foundational vocabulary shared across all thematic units.

The surrounding nodes represent different learning topics.

Each thematic unit contains its own lessons, exercises, and progression.

The learner should be able to:

- Start learning foundational vocabulary.
- Explore different thematic units.
- Open individual units.
- View their lessons.
- Start lessons.
- See completed lessons.
- Track progress.
- Return to the overall map.
- Choose what to learn next without being forced through a strictly linear course.

This feature should be a complete learning experience, not simply a decorative diagram.

# 4. Main Radial Map

The central screen is the most important part of this feature.

Create a circular map with the following structure.

## Central node

Position a large circular node in the exact center of the map.

The node should contain:

- A book or vocabulary icon.
- Title: Core Vocabulary.
- Subtitle: Common words for everyday conversations.
- A progress indicator.
- A completion percentage.
- A visual indication of whether the user has started learning.

Example:

Core Vocabulary

Common words for everyday conversations

92% complete

The central node should be visually dominant.

Use a white circular background, blue outline, subtle glow, and a soft shadow.

The node should be interactive.

When tapped, open the Core Vocabulary unit.

The central vocabulary unit should be treated as the foundational unit of the entire map.

However, do not force users to complete it before accessing every other thematic unit.

## Connecting lines

Connect the central Core Vocabulary node to each surrounding thematic unit.

Use subtle, thin lines.

The lines should:

- Be visible against the background.
- Use a light blue or lavender color.
- Remain behind the nodes.
- Have a consistent thickness.
- Avoid crossing through the text inside nodes.

The connections should visually communicate that the central vocabulary is shared across all units.

The lines should not imply that users must complete every unit in a specific order.

---

## Individual lesson nodes

Each thematic unit should have smaller lesson nodes branching outward from it.

These should be visible around the thematic unit, similar to a small skill tree.

Each lesson node should visually represent its status:

- Not started.
- Available.
- In progress.
- Completed.
- Locked, if prerequisites are genuinely required.

Use visual indicators such as:

- Empty circles for uncompleted lessons.
- Green checkmarks for completed lessons.
- A highlighted node for the current lesson.
- A subtle glow for the next recommended lesson.

Do not lock lessons simply to create artificial linear progression.

The user should be able to access available lessons in their chosen order.

When the map is displayed at a smaller size, individual lesson nodes can be simplified or hidden until the user opens the corresponding thematic unit.

# 5. Mobile Layout and Map Navigation

The primary target is Android mobile devices.

The map must be optimized for touch interaction.

The radial layout should adapt to the available screen size.

## Mobile behavior

On mobile:

- Use the available screen area efficiently.
- Keep the central node visually centered.
- Keep thematic units arranged around it.
- Prevent the map from being clipped unexpectedly.
- Avoid placing important nodes underneath the system navigation bar.
- Ensure all interactive elements have comfortable touch targets.
- Support vertical scrolling where necessary.
- Support pinch-to-zoom if appropriate.
- Support dragging or panning around the map if the layout exceeds the viewport.

The map should not become unusable on smaller screens.

If all thematic units cannot comfortably fit around the central node, use a controlled zoomable or pannable map rather than shrinking the nodes to unreadable sizes.

A reasonable default zoom level should show the central node and most surrounding thematic units.

## Desktop and tablet behavior

If the application is opened on a larger screen:

- Center the map within the available content area.
- Increase the map's available size.
- Maintain the radial arrangement.
- Avoid stretching the circular nodes.
- Keep the layout visually balanced.

## Technical implementation

Prefer an SVG-based connection layer or another solution that allows the lines and nodes to remain aligned.

The connection layer must not intercept touch events intended for the nodes.

The map should resize correctly when the viewport changes.

Avoid hardcoding absolute coordinates that only work for one screen size.

If using SVG, ensure it scales correctly and maintains its aspect ratio.

If using CSS positioning, calculate or derive positions in a maintainable way.

Do not introduce a heavy graph visualization library unless the existing project already uses one or there is a clear technical need.

- Closing and reopening the application.
- Changing the selected unit.
- Returning to the map.

# 11. Visual States and Animations

### Default state

### Selected unit

The selected unit should receive a subtle visual highlight.

### Unit expansion

### Completed lesson

Display a green checkmark or equivalent completion indicator.

### In-progress lesson

Display a distinct visual indicator.

### Locked lesson

Use a muted appearance and explain the actual prerequisite if one exists.

### Recommended lesson

Use a subtle highlight to indicate the next suggested learning activity.

- Node selection: 150–250 ms.

- Progress indicator updates: 300–500 ms.
